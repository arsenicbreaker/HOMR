# Superhuman — Design System

## Overview

Superhuman is luxury email productivity expressed through design. The visual language feels like opening a fine envelope: an immaculately white canvas with a single dramatic gesture of color commanding attention. The hero section is a cinematic purple gradient — {hero-warm} deep twilight washing into {hero-glow} lavender glow — overlaid with confident white typography. Below this dramatic entrance, the page unfolds into a predominantly white content body with {ink} charcoal text, creating a stark yet refined reading experience.

The design philosophy is **maximum confidence through minimum decoration**. Warm, muted accent colors replace bright CTAs. Borders are subtle and minimal. The sole accent — Lavender Glow ({color.primary}) — appears sparingly, making every occurrence feel intentional. It is a productivity tool that presents itself like a luxury brand: every pixel earns its place, nothing is merely decorative.

**Emotional response**: Sophisticated, calm, precise. The user feels they are entering a tool built for people who value time — where speed and clarity are the ultimate luxuries. The confidence of the compressed display typography, the warmth of the cream-toned surfaces, the restraint of a single accent color — all signal a product that respects attention and rewards focus.

## Typography

### Font Family

**Super Sans VF** — a custom variable font with a non-standard weight axis (460, 540, 600, 700). These weights sit deliberately between conventional font categories: 460 is heavier than Regular (400) but lighter than Medium (500), creating a typographic texture that feels subtly "off" in a confident way — slightly heavier than expected, never quite bold. The same font family serves both display and body roles for consistency.

**Font stack**: `{typography.fontFamily}` — Super Sans VF with system-ui and cross-platform sans-serif fallbacks.

**Font substitutes**: When Super Sans VF is unavailable, the stack degrades to `system-ui, -apple-system, Segoe UI, Roboto, sans-serif`. Note that substitute fonts will render at standard weight stops (400, 500, 600, 700), so the intended 460 and 540 weights will map to 400 and 500 respectively — a subtle but noticeable shift in texture.

### Hierarchy

| Token | Font | Size | Weight | Line Height | Letter Spacing | Use |
|-------|------|------|--------|-------------|----------------|-----|
| `display-xl` | Super Sans VF | 64px | 540 | 0.96 | 0 | Hero headlines, primary value props |
| `heading-lg` | Super Sans VF | 48px | 460 | 0.96 | -1.32px | Section titles, feature intros |
| `body-md` | Super Sans VF | 16px | 460 | 1.50 | 0 | Primary reading text |
| `button-md` | Super Sans VF | 16px | 600 | 1.0 | 0 | Button labels, navigation |
| `caption` | Super Sans VF | 14px | 500 | 1.20 | -0.315px | Metadata, timestamps, labels |
| `code-md` | JetBrains Mono | 14px | 460 | 1.50 | 0 | Inline code, snippets |

### Principles

1. **Extreme display compression**: Headlines at {typography.display-xl.lineHeight} line-height collapse lines nearly on top of each other, creating dense typographic blocks that feel architectural and powerful. The 64px display size (`display-xl`) at weight 540 is the most compressed — a deliberate tension that forces attention.

2. **Body generosity**: In deliberate contrast, body text at {typography.body-md.lineHeight} line-height is extremely spacious, ensuring comfortable extended reading after the dense headline impact. The 460 weight is the workhorse — confident without aggression.

3. **Selective negative tracking**: Letter-spacing is applied surgically — {typography.heading-lg.letterSpacing} on 48px headings, 0 on body text. The larger the text, the tighter the tracking. This creates a visible hierarchy where display text pulls together and body text breathes freely.

4. **Non-standard weight axis**: Weights 460 and 540 are deliberately between conventional Regular (400) and Medium (500). Combined with the tight spacing, this creates a typographic voice that is unmistakably Superhuman — confident, precise, unconventional.

### Note on Font Substitutes

When Super Sans VF cannot be loaded (slow networks, ad-blockers, restricted environments), the fallback to `system-ui` or `-apple-system` is acceptable but will shift weight rendering. The non-standard 460/540 stops will collapse to 400/500. Design reviews should verify that typographic texture remains intentional under substitute fonts. For the mono role, JetBrains Mono (`code-md` fontFamily) provides a consistent coding experience.

## Layout & Spacing

### Semantic Spacing Scale

The spacing system follows an 8px base grid, scaling up geometrically from `xs` (8px) to `band` (120px).

| Token | Value | Usage |
|-------|-------|-------|
| xxs | {spacing.xxs} | Micro spacing, icon margins |
| xs | {spacing.xs} | Tight element gaps, inline spacing |
| sm | {spacing.sm} | Component internal padding, button gaps |
| md | {spacing.md} | Default element spacing, form field gaps |
| lg | {spacing.lg} | Card padding, section element spacing |
| xl | {spacing.xl} | Card group margins, feature block gaps |
| xxl | {spacing.xxl} | Internal section padding |
| xxxl | {spacing.xxxl} | Major section separation |
| section | {spacing.section} | Between major page sections |
| band | {spacing.band} | Maximum separation, hero-to-content transition |

### Grid & Container

- **Max content width**: ~1200px, centered with auto margins
- **Column patterns**: Full-width hero band → centered single-column content → 2–3 column feature grids
- **Feature grid**: Even column distribution for product showcases, collapsing to single column on mobile

### Whitespace Philosophy

Confident emptiness defines the layout. Every section has room to breathe — generous padding between content blocks signals premium positioning. The hero is cinematic and spacious; content sections become denser with feature grids, then expand again for call-to-action bands. Product screenshots fill space that lesser sites would fill with marketing copy. Progressive density — from spacious hero → dense feature grid → open CTA — creates a rhythmic reading experience.

## Elevation & Depth

### Level Table

Superhuman's elevation system is remarkably restrained. Depth is communicated primarily through borders and color contrast rather than box-shadows.

| Level | Treatment | Use Case |
|-------|-----------|----------|
| Level 0 | `elevation-level0`: none | Primary page canvas, flat content surfaces |
| Level 1 | `elevation-level1`: `0 0 0 1px #dcd7d3` (light) / `0 0 0 1px #3a3938` (dark) | Card containment, subtle separation |
| Level 2 | `elevation-level2`: `0 0 0 1px #292827` (light) / `0 0 0 1px rgba(255,255,255,0.6)` (dark) | Header elements, dark section dividers, emphasis borders |
| Level 3 | `elevation-level3`: `0 4px 16px rgba(0,0,0,0.08)` (light) / `0 4px 20px rgba(203,183,251,0.1)` (dark) | Product screenshot containers, elevated cards with subtle glow |
| Level 4 | `elevation-level4`: `0 0 0 1px rgba(255,255,255,0.2)` | Elements on the dark hero gradient — ghostly containment |
| Level 5 | `elevation-level5`: gradient (#1b1938 → #cbb7fb) / dark: (#1b1938 → #3a2468) | Hero gradient — the primary depth device |

### Decorative Depth

- **Hero gradient**: The `hero-warm` to `hero-glow` gradient transition is the primary depth device — a cinematic curtain effect that creates massive atmospheric depth through color shift rather than shadows.
- **Lavender accents**: `hero-glow` elements float above the dark gradient (`hero-warm`), creating a stellar, atmospheric effect.
- **Opacity layering**: Semi-transparent whites (`on-dark-mute`) on the hero gradient create layered depth — 95% opacity for primary text, 72% for secondary, 80% for decorative elements.
- **No glassmorphism**: Depth comes from color and opacity, not backdrop blur. Screenshots themselves create depth by showing a layered UI within the flat page.

## Shapes

### Border Radius Scale

Superhuman uses a deliberately binary radius system — only two corner sizes in active use: 8px (small) and 16px (large). No micro-rounding (2px), no pill shapes (9999px for controls only). This radical simplicity reinforces the brand's precision.

| Token | Value | Usage |
|-------|-------|-------|
| none | {rounded.none} | Hero bands, full-bleed sections, navigation bars |
| xs | {rounded.xs} | Checkbox indicators, small control elements |
| sm | {rounded.sm} | Buttons, inputs, selects, textareas, badges, tabs, alerts, progress bars |
| md | {rounded.md} | Larger interactive elements (12px radius) |
| lg | {rounded.lg} | Cards, modals, panels — the signature large radius |
| full | {rounded.full} | Avatars, radio buttons, switches — purely circular elements |

### Photography Geometry

- **Product screenshots**: Wide landscape ratio (~16:9), displayed full-width within containers, {rounded.lg} corners, minimal framing
- **Hero imagery**: Cinematic full-bleed composition, crops responsively maintaining dramatic center focus
- **Contributor avatars**: Circular ({rounded.full}), contained within 40–48px bounds
- **No art direction changes**: Same image compositions across all breakpoints, with responsive scaling

## Do's and Don'ts

### Do

- Use Super Sans VF at weight 460 as the default — it is slightly heavier than regular, which is the brand's typographic signature
- Keep display headlines at {typography.display-xl.lineHeight} line-height — the compression is intentional and powerful
- Limit border-radius to {rounded.sm} (small) and {rounded.lg} (large) — the binary radius system is deliberate
- Apply negative letter-spacing on headlines only ({typography.heading-lg.letterSpacing}) — body text stays at 0
- Use `primary` ({color.primary}) as the only accent color — it is the sole color departure from the neutral palette
- Let product screenshots be the primary visual content — the UI sells itself
- Maintain the dramatic hero gradient as a singular gesture — the rest of the page is white
- Use warm cream-toned surfaces (`bone`, `divider`) instead of cool grays — warmth signals luxury
- Apply `ring-focus` ({ring-focus}) for keyboard focus states — accessibility without visual noise

### Don't

- Use conventional font weights (400, 500, 600) — Superhuman's 460 and 540 are deliberately between standard stops
- Add bright or saturated CTA colors (blue, green, red) — interactive elements use `primary` or subtle cream tones
- Introduce additional accent colors beyond `primary` — the palette is deliberately restrained to one accent
- Apply shadows generously — depth comes from borders, color contrast, and photography, not box-shadows
- Use tight line-height on body text — display is compressed (0.96) but body is generous (1.50)
- Add decorative elements, icons, or illustrations — Superhuman relies on product UI and minimal typography
- Create pill-shaped buttons — the system uses {rounded.sm} radius, not rounded pills
- Use pure black (#000000) for text — `ink` (#292827) is warmer and softer
- Override the token system — always reference tokens via `{color.*}`, `{typography.*}`, `{spacing.*}` syntax

## Responsive Behavior

### Breakpoints

| Name | Width | Key Changes |
|------|-------|-------------|
| Mobile | <768px | Single column layout, hero text reduces to ~36px, stacked feature cards, hamburger nav |
| Tablet | 768px–1024px | 2-column feature grid begins, hero text ~48px, nav partially visible |
| Desktop | 1024px–1440px | Full layout, 64px hero display (`display-xl`), multi-column feature grid, full nav |
| Large Desktop | >1440px | Max-width container centered at ~1200px, generous side margins |

### Touch Targets

- Buttons: Minimum 44px height (`button-primary` height: 44px) with comfortable padding — meets WCAG touch target guidelines
- Nav links: 16px text with adequate surrounding padding, minimum 44px tap area
- Mobile CTAs: Full-width buttons for easy thumb reach on narrow screens
- Links: Underline decoration provides clear tap affordance at all sizes
- Form inputs: 44px height (`text-input` height: 44px), 12px+ padding for comfortable input

### Collapsing Strategy

- **Navigation**: Full horizontal nav → hamburger menu on mobile; sticky behavior with background transition
- **Hero text**: 64px display → 48px → ~36px across breakpoints — proportional scaling
- **Feature grid**: Multi-column product showcase → 2-column (tablet) → single stacked column (mobile)
- **Product screenshots**: Scale within containers maintaining landscape aspect ratios (~16:9)

## Iteration Guide

1. **Focus on one component at a time** — When refining the design system, work through components individually (e.g., buttons → inputs → cards) rather than making global changes.

2. **Reference tokens directly** — Always use `{color.primary}`, `{typography.body-md}`, `{rounded.lg}`, `{component.button-primary}` syntax in specifications. Never write raw hex or px values in documentation without wrapping in token references.

3. **Verify font weights first** — Confirm weight 460 for body and 540 for display. The non-standard weights are the most commonly missed detail when adapting the system.

4. **Check display line-height** — If headlines look too spaced (visually >0.96), they are wrong. Display compression at {typography.display-xl.lineHeight} is the signature Superhuman typographic move.

5. **Confirm the accent restraint** — The only accent color should be `primary` ({color.primary}). If any other hue appears outside semantic badges, the palette has drifted. If buttons use colors other than `primary` background or canvas background, they are wrong.

6. **Validate radius consistency** — Check that only {rounded.sm} and {rounded.lg} are used for components (plus {rounded.full} for avatars/radios/switches). If any intermediate radius appears (e.g., 6px, 10px, 14px), flag it.

7. **Run dark mode audit** — Every light-mode component must have a corresponding dark-mode value. Use the `colors-dark` mapping table. Verify that borders invert, text inverts with correct opacity, and the hero gradient shifts to `hero-warm` → `#3a2468`.

8. **Keep the hero gradient singular** — The dramatic `hero-warm` → `hero-glow` gradient should appear only once per page. Additional gradients dilute the impact.

9. **Test with substitute fonts** — Load the system without Super Sans VF to verify the fallback stack renders acceptably. Note that 460/540 weights will map to 400/500.

10. **Run validation** — After any component update, verify all tokens resolve correctly against `design-token.json` and `theme.css`.

## Known Gaps

- **Pressed state variants**: Only `button-primary-pressed` is defined. Other components (inputs, cards, tabs) lack explicit pressed/active state tokens. These rely on focus-ring (`ring-focus`) alone.
- **Table component**: No table-specific tokens or component spec. Tables currently inherit card-level styling (`card` background, `divider` borders).
- **Accordion component**: Not yet extracted. Relies on card + divider patterns.
- **Dropdown/menu component**: References `zIndex.dropdown` (100), but no dedicated menu surface, shadow, or item spec exists.
- **Toast/notification**: Not defined in tokens. Alerts serve feedback needs but with no fixed-position or dismiss animation spec.
- **Skeleton loading states**: No skeleton/placeholder tokens defined. Loading relies on muted foreground tones (`stone` opacity).
- **Focus-visible vs focus**: The ring-focus token applies universally; no distinct `:focus-visible` treatment is documented for mouse vs keyboard interaction.
- **Dark mode hero gradient**: The dark-mode hero gradient (`#1b1938` → `#3a2468`) exists in elevation level 5 but is not reflected in page-level documentation of hero behavior in dark mode.
- **Mobile navigation**: `nav-bar` component defined at 60px height, but mobile hamburger menu surface, animation, and overlay behavior are not tokenized.
